### 1. Protocol Overview

**X402** is an open payment protocol supported by Coinbase that enables **pay-per-call** microtransactions for machine-to-machine (M2M) and API monetization scenarios.

**Core Concept**: Reuse HTTP status code `402 Payment Required` to embed payment flows into standard web request/response cycles.

**Key Technologies**:
- HTTP 402 status code for payment triggers
- EIP-3009 `transferWithAuthorization` for gasless payments
- Ethereum L2 (Base) for low-cost settlements
- Batch settlement (x402x extension) for gas optimization

### 4. EIP-3009 Signature Format

According to EIP-3009, the signature is generated by signing a structured message:

```
TRANSFER_WITH_AUTHORIZATION_TYPEHASH = keccak256(
  "TransferWithAuthorization(address from,address to,uint256 value,uint256 validAfter,uint256 validBefore,bytes32 nonce)"
)

digest = keccak256(
  abi.encodePacked(
    "\\x19\\x01",
    DOMAIN_SEPARATOR,
    keccak256(abi.encode(
      TRANSFER_WITH_AUTHORIZATION_TYPEHASH,
      from,
      to,
      value,
      validAfter,
      validBefore,
      nonce
    ))
  )
)

signature = sign(digest, privateKey)
```

**Key Parameters**:
- `DOMAIN_SEPARATOR`: EIP-712 domain separator for the token contract
- `nonce`: Must be unique per authorization (use `keccak256(abi.encodePacked(from, timestamp, randomness))`)
- `validBefore`: Should be reasonable (e.g., 1 hour from now)

### 5. Integration with BatchPaymentPageV2

**Current Flow** (Parallel ETH transfers):
1. User uploads CSV with payment data
2. System validates all entries
3. Transactions sent in batches of 5 (parallel)
4. Each transaction requires gas from sender

**New X402 Flow** (Gasless batch settlement):
1. User uploads CSV with payment data
2. System validates all entries
3. **Generate EIP-3009 signatures for each payment**
4. **Collect all signatures into batch array**
5. **Call `X402BatchSettlement.batchTransferWithAuthorization` once**
6. Relayer pays gas, users only sign authorizations

**Benefits**:
- Users don't need ETH for gas
- Single on-chain transaction (massive gas savings)
- Atomic batch execution (all succeed or all fail in strict mode)
- Better UX for non-crypto-native users

### 6. Technical Challenges

**Challenge 1: DOMAIN_SEPARATOR**
- Each EIP-3009 token has its own domain separator
- Must query token contract for `DOMAIN_SEPARATOR()` before signing

**Challenge 2: Nonce Generation**
- Must be unique per authorization
- Must track used nonces to prevent replay attacks
- Recommend: `keccak256(abi.encodePacked(userAddress, Date.now(), randomBytes(32)))`

**Challenge 3: Relayer Service**
- Who pays the gas for batch settlement?
- Options:
  - Protocol Bank backend service (centralized relayer)
  - User pays gas for batch transaction (defeats "gasless" purpose)
  - Charge small fee per payment to cover gas costs

**Challenge 4: Token Support**
- Real USDC on Base supports EIP-3009
- Sepolia testnet needs mock USDC with EIP-3009
- Must deploy and test with mock token first
