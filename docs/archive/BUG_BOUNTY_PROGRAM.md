## 📋 计划概述

Protocol Bank Bug Bounty 计划旨在鼓励安全研究人员和白帽黑客发现和报告我们智能合约和应用程序中的安全漏洞。我们相信通过社区的力量，可以构建更安全、更可靠的去中心化支付平台。

**计划目标**：
- 在主网部署前发现并修复所有关键和高危漏洞
- 建立与安全社区的长期合作关系
- 提升 Protocol Bank 的整体安全性

**计划范围**：
- ✅ 智能合约（Solidity）
- ✅ 前端应用（React）
- ✅ API 后端（如有）
- ❌ 第三方依赖库（除非是我们的配置问题）
- ❌ 社会工程攻击
- ❌ 物理攻击

## 💰 奖励等级

### 智能合约漏洞

| 严重性 | 描述 | 奖励范围 | 示例 |
|--------|------|----------|------|
| **Critical** | 可导致资金损失或合约完全失效 | $5,000 - $10,000 | 重入攻击、整数溢出导致的资金盗取 |
| **High** | 可导致部分资金损失或重要功能失效 | $2,000 - $5,000 | 权限绕过、逻辑错误导致的资金锁定 |
| **Medium** | 可导致功能异常但不影响资金安全 | $500 - $2,000 | Gas 优化问题、非关键逻辑错误 |
| **Low** | 代码质量问题或轻微的功能缺陷 | $100 - $500 | 文档错误、事件缺失 |

### 前端/后端漏洞

| 严重性 | 描述 | 奖励范围 | 示例 |
|--------|------|----------|------|
| **Critical** | 可导致用户资金或私钥泄露 | $3,000 - $5,000 | XSS 导致私钥泄露、CSRF 导致未授权交易 |
| **High** | 可导致用户数据泄露或服务中断 | $1,000 - $3,000 | SQL 注入、认证绕过 |
| **Medium** | 可导致用户体验下降或信息泄露 | $300 - $1,000 | 信息泄露、会话劫持 |
| **Low** | 轻微的安全或隐私问题 | $50 - $300 | 不安全的 HTTP 头、弱密码策略 |

## 🎯 漏洞范围

### 智能合约

**在范围内**：
- ✅ **StreamPayment.sol** - 流支付合约
  - 重入攻击
  - 整数溢出/下溢
  - 访问控制问题
  - 业务逻辑错误
  - Gas 优化问题

- ✅ **未来的 ERC-8004 合约**（一旦部署）
  - AgentRegistry.sol
  - ReputationRegistry.sol
  - ValidationRegistry.sol

**不在范围内**：
- ❌ OpenZeppelin 库（除非是我们的配置问题）
- ❌ 以太坊协议本身
- ❌ 测试合约（MockERC20.sol）

### 前端应用

**在范围内**：
- ✅ **Web 应用** (https://www.protocolbanks.com)
  - XSS (跨站脚本攻击)
  - CSRF (跨站请求伪造)
  - 认证和授权问题
  - 私钥/助记词泄露
  - 钱包连接安全

**不在范围内**：
- ❌ 第三方库（React, Vite 等）
- ❌ CDN 和托管服务（Vercel）
- ❌ 浏览器插件（MetaMask）

### API 后端

**在范围内**（如有）：
- ✅ API 端点安全
- ✅ 认证和授权
- ✅ 数据验证
- ✅ 速率限制

## 📝 报告流程

### 1. 发现漏洞

在测试过程中，请遵守以下规则：
- ✅ 只在测试网（Sepolia）上测试
- ✅ 不要攻击主网合约（一旦部署）
- ✅ 不要公开披露漏洞
- ✅ 不要利用漏洞获取个人利益
- ❌ 不要进行 DoS 攻击
- ❌ 不要破坏其他用户的数据

### 2. 提交报告

**通过 Immunefi 提交**（推荐）：
1. 访问 https://immunefi.com/bounty/protocolbank/
2. 点击 "Submit a Bug"
3. 填写漏洞详情

**通过 Email 提交**（备选）：
1. 发送邮件至: security@protocolbank.com
2. 使用 PGP 加密（公钥见下方）
3. 包含以下信息：
   - 漏洞描述
   - 影响范围
   - 复现步骤
   - PoC 代码（如有）
   - 修复建议（可选）

**报告模板**：
```
漏洞标题: [简短描述]

严重性: [Critical / High / Medium / Low]

漏洞描述:
[详细描述漏洞的性质和影响]

影响范围:
- 受影响的合约/组件: [...]
- 潜在损失: [...]
- 受影响的用户: [...]

复现步骤:
1. [步骤 1]
2. [步骤 2]
3. [...]

PoC 代码:
```solidity
// 或 JavaScript 代码
```

修复建议:
[可选，但会增加奖励]

联系方式:
- Email: [...]
- Telegram: [...]
- Discord: [...]
```

### 3. 等待响应

- **确认**: 我们将在 **24 小时内**确认收到报告
- **初步评估**: 我们将在 **3 个工作日内**进行初步评估
- **详细分析**: 我们将在 **7 个工作日内**完成详细分析
- **奖励发放**: 漏洞修复后 **14 个工作日内**发放奖励

### 4. 修复和验证

- 我们将修复漏洞并请您验证修复效果
- 验证通过后，我们将发放奖励
- 您可以选择是否在致谢名单中公开您的名字

## 🚫 不符合奖励的情况

以下情况将**不会**获得奖励：

1. **已知漏洞**: 已经被其他研究人员报告
2. **低质量报告**: 缺乏详细信息或复现步骤
3. **不在范围内**: 不在 Bug Bounty 范围内的漏洞
4. **违反规则**: 违反测试规则（如攻击主网）
5. **公开披露**: 在我们修复前公开披露漏洞
6. **恶意利用**: 利用漏洞获取个人利益

## 📞 常见问题 (FAQ)

### Q1: 我可以测试主网合约吗？

**A**: 不可以。请只在 Sepolia 测试网上测试。攻击主网合约将被视为恶意行为。

### Q2: 我可以公开披露漏洞吗？

**A**: 不可以，至少在我们修复漏洞前不可以。我们承诺在修复后 90 天内公开披露（除非您不同意）。

### Q3: 我可以匿名报告漏洞吗？

**A**: 可以。我们尊重您的隐私，但您需要提供一个联系方式以便我们与您沟通。

### Q4: 奖励需要多久才能发放？

**A**: 通常在漏洞修复并验证后 14 个工作日内发放。

### Q5: 我可以报告多个漏洞吗？

**A**: 当然可以！每个有效的漏洞都会获得相应的奖励。

### Q6: 如果我不同意严重性评估怎么办？

**A**: 您可以提供更多证据来支持您的评估。我们会重新审查并给出最终决定。

### Q7: 我可以在 Twitter 上分享我发现了漏洞吗？

**A**: 在我们修复并公开披露前，请不要分享任何细节。修复后，我们欢迎您分享（并会在致谢名单中提及您）。
