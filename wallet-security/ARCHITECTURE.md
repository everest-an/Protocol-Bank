# 机构级 MPC 钱包基础设施架构设计

**版本:** 1.0
**作者:** Manus AI & User

## 1. 概述与目标

本文档旨在详细阐述我们即将构建的机构级 MPC (多方安全计算) 钱包基础设施的核心架构设计。该项目旨在开发一个高度安全、可靠且具备前瞻性的数字资产安全平台，其安全级别对标 Fireblocks 等行业领导者。

核心目标是消除私钥的单点风险，并通过多层次的纵深防御体系，全面抵御外部攻击、内部威胁和人为操作失误。我们将采用模块化、分阶段的方式进行开发，首先构建一个功能完备的核心原型 (MVP)。

## 2. 核心技术选型

经过深入讨论，我们确定了以下核心技术组合，以平衡安全性、性能和开发效率。

### 2.1. MPC 协议库: ZenGo `multi-party-ecdsa`

我们将采用 ZenGo 开源的 `multi-party-ecdsa` 库作为我们 MPC 功能的基石。

- **选型理由:**
  - **专注与成熟:** 该库专门为 ECDSA 签名算法设计，已在业界得到广泛应用和验证，非常适合比特币、以太坊等主流区块链。
  - **内存安全:** 采用 Rust 语言编写，其内存安全的特性可以从根本上杜绝许多常见的底层安全漏洞，是构建金融级应用的首选。
  - **社区验证:** 拥有清晰的学术论文支持和一定的社区基础，便于我们进行集成和二次开发。

### 2.2. 加密方案: Kyber + AES256 混合加密

为了保护传输中和静态存储的敏感数据（尤其是私钥分片），我们将采用前沿的后量子混合加密方案。

- **工作原理:**
  1. 使用高效的 **AES256** 对称加密算法加密实际的敏感数据（如私钥分片）。
  2. 使用 **CRYSTALS-Kyber** (NIST PQC 标准) 非对称加密算法来加密 AES256 的会话密钥。

- **优势:**
  - **量子安全:** Kyber 能够抵御未来量子计算机的攻击，确保了我们系统的长期安全性。
  - **高性能:** 实际的数据加密由高效的 AES256 完成，保证了系统的性能和吞吐量。
  - **前瞻性:** 使我们的系统从第一天起就具备了面向未来的安全能力。

## 3. “三权分立”系统架构

我们将借鉴顶级安全实践，设计一个将 **计算**、**存储** 和 **策略** 彻底解耦的“三权分立”架构。

### 3.1. MPC 签名节点 (计算层)

- **职责:** 唯一职责是执行 MPC 密码学计算，生成交易签名。
- **特性:** 节点本身无状态，不存储长期密钥。私钥分片仅在使用时加载到安全内存中，用后即焚。节点将部署在高度隔离的网络环境中，以最小化攻击面。

### 3.2. 加密存储服务 (存储层)

- **职责:** 安全地持久化存储 **加密后** 的私钥分片。
- **特性:** 存储层对存储内容“零知识”，它无法解密自己存储的数据。只有授权的 MPC 节点才能请求访问特定的加密分片。

### 3.3. 策略与审批引擎 (策略层)

- **职责:** 作为系统的“大脑”和风控中心，处理所有交易请求的授权和审批。
- **特性:** 管理员可在此定义详细的交易规则（如额度、白名单、审批流）。只有当一笔交易满足所有策略并通过审批后，策略引擎才会生成一次性授权令牌，触发计算层的签名操作。

## 4. 下一步行动计划

1. **搭建 Rust 开发环境** 并集成 `multi-party-ecdsa` 库。
2. **开发 PoC (概念验证):** 编写脚本，模拟两个独立的参与方完成一次完整的密钥生成和协同签名流程。
3. **实现加密模块:** 基于上述设计，开发 Kyber+AES256 混合加密模块，用于保护 PoC 中生成的密钥分片。
